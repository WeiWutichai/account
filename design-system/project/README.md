# AccountSystem · Carbon TH

ระบบออกแบบสำหรับ AccountSystem (ระบบบัญชี SaaS ของ Innovera) ต่อยอดจาก IBM Carbon Design System ปรับให้เหมาะกับอักษรไทยและงานบัญชี เป้าหมายคือหน้าตาที่นักบัญชีไทยคุ้นเหมือนโปรแกรมองค์กรทั่วไป ไม่ใช่หน้าตาที่ดูเป็น AI

## หลัก 5 ข้อ

1. **ใช้ Carbon ไม่ประดิษฐ์สไตล์เอง** — component, spacing, สี ตาม Carbon White/Gray 100 ยกเว้นที่ระบุในเอกสารนี้
2. **ตารางและฟอร์มเป็นหลัก ไม่ใช่การ์ด** — งานบัญชีคือการอ่านและกรอกตัวเลข แผงใช้เส้นขอบ 1 px (`border-subtle`) ไม่ใช้เงา เงามีเฉพาะเมนูลอย (`shadow-menu`)
3. **สีหลักสีเดียว + เทา** — `interactive` ใช้กับปุ่มหลัก แท็บที่เลือก และลิงก์เท่านั้น สีอื่น 4 สีมีความหมายตายตัวและมาคู่ข้อความเสมอ (ดู สถานะ)
4. **ความสม่ำเสมอก่อนความสวย** — ปุ่มหลัก 1 ปุ่มต่อหน้า ตำแหน่ง action เหมือนกันทุกหน้า รูปแบบตัวเลขเหมือนกันทุกตาราง
5. **WCAG 2.2 AA เป็นขั้นต่ำ** — ข้อความ 4.5:1, ขอบ control 3:1, focus มองเห็นทุกจุด (`border-focus` 2 px), เป้าคลิก ≥ 24×24 px, ใช้ด้วยคีย์บอร์ดได้ครบ

## ตัวอักษร

- หน้าจอใช้ `IBM Plex Sans Thai` คู่กับ `IBM Plex Sans` (ตระกูลเดียวกับ Carbon) โหลดจาก Google Fonts น้ำหนัก 400/500/600
- เอกสารพิมพ์ (ใบกำกับภาษี, 50 ทวิ, รายงานภาษี) ใช้ `Sarabun` เพราะเป็นฟอนต์ที่แบบฟอร์มราชการคุ้นเคย
- ขนาด: เนื้อหา 15 px, ตาราง 14 px, label 13 px, ขั้นต่ำ 12 px (เฉพาะ meta) — อักษรไทยมีสระบน/ล่างจึงต้องใหญ่กว่าอังกฤษ 1 ขั้น และ line-height 1.6 สำหรับเนื้อหา 1.4 ในตาราง
- หัวข้อหน้า 22 px น้ำหนัก 600 ไม่ใช้ตัวเอียง (ไทยอ่านยาก) ไม่มีหัวข้อใหญ่กว่า 24 px ในหน้าแอป

## ตัวเลข (กฎที่ใช้ทุกหน้า)

- จำนวนเงินชิดขวาเสมอ ทั้งหัวคอลัมน์และเซลล์
- `font-variant-numeric: tabular-nums` ทุกที่ที่ตัวเลขเรียงเป็นคอลัมน์ ไม่ใช้ฟอนต์ monospace
- ทศนิยม 2 ตำแหน่ง + คอมมาคั่นหลักพัน `1,284,350.00` ไม่ใส่ ฿ ในตาราง ใส่สกุลเงินที่หัวคอลัมน์เมื่อมีหลายสกุล
- ค่าติดลบในงบการเงินใช้วงเล็บ `(1,200.00)` ในหน้าจอทำงานใช้ `−1,200.00` สีแดง (`amount-negative`) เป็นตัวเสริม ไม่ใช่ตัวบอกเดียว
- ค่าศูนย์ในคอลัมน์ Dr/Cr แสดงเป็นช่องว่าง ไม่ใช่ `0.00`
- วันที่ `DD/MM/YYYY` ตามค่าตั้งผู้ใช้ (พ.ศ./ค.ศ.) เอกสารภาษีพิมพ์เป็น พ.ศ.

## สถานะ (4 สี ความหมายตายตัว)

| ความหมาย | token | ใช้กับ |
| --- | --- | --- |
| สำเร็จ | `status-success-*` | ลงบัญชีแล้ว, ชำระแล้ว, กระทบยอดแล้ว, ดุล |
| รอ | `status-warning-*` | รออนุมัติ, รอตรวจ, ครบกำหนดใน 7 วัน |
| ผิดพลาด | `status-error-*` | เกินกำหนด, ไม่ดุล, ยกเลิก, ล้มเหลว |
| ข้อมูล | `status-info-*` | ร่าง, จากระบบภายนอก (TMS), หมายเหตุ |

ใช้ผ่าน component `StatusTag` เท่านั้น ห้ามใส่สีสถานะกับข้อความโดยตรง สีต้องมาคู่กับคำเสมอ

## ระยะและเลย์เอาต์

- ใช้เฉพาะ `space-01` … `space-08` (2–48 px)
- มุม: control และช่องกรอกเหลี่ยม (`radius-none`) ตาม Carbon; tag แผง เมนูลอย modal ใช้ `radius-sm` 4 px
- เมนูซ้าย `sidebar` 256 px พับเหลือ 48 px พื้นเทา (`bg-layer-1`) ไม่ใช้สีเข้ม; แถบบนแสดงบริษัทและงวดที่เปิดอยู่เสมอ
- หน้าเนื้อหาเต็มความกว้าง (ตารางต้องการพื้นที่) ฟอร์มเอกสารกว้างสูงสุด `form-max` 1200 px
- รองรับจอ 1366 px ขึ้นไปเป็นหลัก มือถือใช้ดูและอนุมัติ ไม่ต้องกรอกเอกสารเต็มรูปบนมือถือ

## รูปแบบหน้าจอมาตรฐาน 5 แบบ

1. **รายการเอกสาร** — แท็บสถานะ (ทั้งหมด / ร่าง / รออนุมัติ / ค้างชำระ / เกินกำหนด) + ช่องค้นหาทันที + ตัวกรองขั้นสูงซ่อนไว้ → `DataTable` แถว 40 px คลิกแถวเปิดเอกสาร เลือกหลายแถวแล้วแถบ batch action แทนที่ toolbar
2. **ฟอร์มเอกสาร** — หัวเอกสาร (คู่ค้าซ้าย วันที่/เลขที่ขวา) → ตารางบรรทัดแก้ไขได้ → หมายเหตุซ้ายล่าง ยอดรวมขวาล่าง → แถบปุ่มติดด้านล่าง ปุ่มหลัก 1 ปุ่ม; เลียนแบบใบกำกับกระดาษ
3. **ตัวอย่างการลงบัญชี** — แท็บ "สำหรับนักบัญชี" หรือแผงข้าง แสดง Dr/Cr ก่อนบันทึก (`JournalPreview`) เห็นเฉพาะผู้มีสิทธิ์
4. **กระทบยอดธนาคาร** — สองคอลัมน์: รายการ statement ซ้าย คู่ที่ระบบแนะนำขวา ปุ่มจับคู่ทีละแถว
5. **รายงาน** — พารามิเตอร์ด้านบน (งวด สาขา มิติ) → ตารางแถว 32 px รูปแบบงบ → คลิกตัวเลขดูรายการ → ส่งออก

หน้าแรกหลังเข้าระบบคือ **คิวงาน** (รออนุมัติ, ครบกำหนดรับ/จ่าย 7 วัน, statement ยังไม่จับคู่, ขั้นปิดงวด) ไม่ใช่กราฟหรือตัวเลขใหญ่

## ฟอร์ม

- Label อยู่บนช่องเสมอ ไม่ใช้ placeholder แทน label
- Error ใต้ช่องบอกวิธีแก้ + สรุป error บนสุดของฟอร์ม
- Tab ไล่ได้ครบตามลำดับกรอก, Enter ที่บรรทัดสุดท้ายเพิ่มบรรทัด, Ctrl/⌘+S บันทึกร่าง
- ช่องเงินจัดรูปแบบเมื่อออกจากช่อง ยอดรวมคำนวณทันทีแต่คำนวณจริงที่ server
- การกระทำที่ย้อนไม่ได้ (ยกเลิกเอกสาร ปิดงวด) ใช้ `btn-danger` และต้องยืนยันพร้อมบอกผลกระทบ

## สิ่งที่ห้าม

Gradient, กระจกฝ้า, เงาบนแผงในหน้า, การ์ดมุมโค้งมาก, เส้นสีหนาด้านเดียวของการ์ด, emoji แทนไอคอน, ตัวเลข KPI ยักษ์, hero ในแอป, อนิเมชันเด้ง, ตัวเอียงกับภาษาไทย, ฟอนต์ mono กับจำนวนเงิน, สีสถานะที่ไม่มีคำกำกับ

- ไอคอน: `@carbon/icons-react` ชุดเดียว
- Lint: stylelint ห้ามค่าสี/ระยะนอก token; axe-core ใน CI ห้ามมี violation ระดับ AA
- ทดสอบด้วยข้อความไทยจริง (ชื่อบริษัทยาว สระซ้อน) ไม่ใช่ lorem ipsum
