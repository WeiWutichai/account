## กติกาที่ใช้ทั้ง 2A
1. **Backend ก่อน UI** — แบบร่าง `.dc.html` ของโมดูลใหม่ยังไม่มี → ทำ DB + posting + service + API + test · UI รอแบบร่างจาก Claude Design (ห้ามเดาหน้าจอ)
2. **เรื่อง [ผู้สอบบัญชี] = config + "รอยืนยัน"** ใน `acct.company_setting` · ค่าตั้งต้นชั่วคราวเขียนไว้ในตารางท้ายไฟล์ · ห้ามฝังเป็นค่าคงที่
3. **โมดูลเปิดต่อบริษัท** (`company.modules` มีอยู่แล้วจากตัวช่วยสร้างบริษัท) · ปิดอยู่ = พฤติกรรม Phase 1 เดิมทุกอย่าง (golden/e2e เดิมต้องผ่านไม่เปลี่ยน)
4. **บัญชีของโมดูล** สร้างเมื่อเปิดโมดูล (upsert ไม่ทับชื่อที่ผู้ใช้แก้) · ไม่แก้ผังใน fixtures เดิม
5. ตัวเลขทดสอบมาจาก fixtures ชุดใหม่ `fixtures/p2a-trading.json` และ `fixtures/p2a-software.json` (**ร่าง รอ Wei ยืนยัน** · ไม่แตะ `sample-company.json`)
6. Decimal ทุกจุด · qty/ต้นทุนต่อหน่วย `NUMERIC(18,4)` · เงิน `NUMERIC(18,2)` · อัตรา FX `NUMERIC(18,6)` · ปัดเศษบรรทัดสุดท้าย
7. ตารางใหม่ทุกตาราง: `company_id` + RLS ENABLE/FORCE + policy tenant (DO $$ loop) · index ขึ้นต้น `company_id` · migration ย้อนได้
8. เอกสารที่ผ่านรายการไม่ลบ — ยกเลิก = void + reversal (รวม stock move ย้อนกลับ)

## INV — สินค้าคงคลัง
- ตาราง: `warehouse` (code, name, branch_code, allow_negative) · `product_unit` (หน่วยซื้อ/ขาย + ตัวคูณ) · `stock_move` (วันที่ สินค้า คลัง qty± ต้นทุน/หน่วย มูลค่า ประเภท source_document_id/line lot/serial journal_id) · `stock_balance` (สินค้า×คลัง qty avg_cost value — ปรับใน transaction เดียวกับ move · ล็อกแถว FOR UPDATE)
- product: `track_stock`, `inventory_account`, `cogs_account`, `reorder_point`, `max_qty`, `barcode`
- เอกสารใหม่: **GR** ใบรับสินค้า (อ้าง PO รับหลายครั้ง) · **GI** เบิกใช้ · **TRF** โอนคลัง · **ADJ** ปรับยอด/ตรวจนับ
- ขาย (IV/ขายสด) บรรทัดสินค้า track_stock → move ออก · ซื้อ (AP) บรรทัดสินค้า → move เข้า (Dr สินค้าคงเหลือแทนค่าใช้จ่าย) · AP อ้าง GR → ล้าง GR/IR
- ต้นทุน: ถัวเฉลี่ยเคลื่อนที่ระดับ สินค้า×คลัง (FR-IN-01) · FIFO = P3 (โครง cost layer ไม่ทำตอนนี้)
- perpetual: ทุก move ออกลง Dr ต้นทุนขาย / Cr สินค้าคงเหลือ · periodic: ไม่ลงต่อ move · ปิดงวดสร้าง JV ปรับสินค้าคงเหลือปลายงวด
- ห้ามติดลบ (เว้นคลังที่ allow_negative) · ขายย้อนวันที่ → คำนวณต้นทุนใหม่ไปข้างหน้า (recost) ภายในงวดที่เปิด
- รายงาน: สต็อกการ์ด · มูลค่าคงเหลือ ณ วันที่ · ถึงจุดสั่งซื้อ · รายงานสินค้าและวัตถุดิบ ม.87(3) (โครง — รูปแบบรอยืนยัน)
- กระทบยอด: เพิ่มจุดตรวจ `inventory_control` มูลค่าคงเหลือ ↔ GL สินค้าคงเหลือ (perpetual)
- บัญชีโมดูล: 1200100 สินค้าคงเหลือ · 2130100 สินค้ารับแล้วรอใบแจ้งหนี้ (GR/IR) · 5020100 ต้นทุนขาย · 5020900 ผลต่างจากการตรวจนับ

## FXB — หลายสกุลเงิน + สาขา
- ตาราง: `currency` (code, name, decimals) · `exchange_rate` (วันที่ สกุล อัตรา แหล่ง) · `branch` (รหัส 5 หลัก ชื่อ ที่อยู่ เลขผู้เสียภาษีสาขา ยื่นแยก)
- document: `fx_rate` NUMERIC(18,6) (currency มีแล้ว) · ยอดในเอกสาร = สกุลเอกสาร · journal = บาท (ยอด × อัตรา ปัดบรรทัดสุดท้าย) · journal_line เก็บ `amount_fx`, `currency`
- รับ/จ่ายสกุลต่างประเทศ: ล้างลูกหนี้/เจ้าหนี้ตามอัตราเดิม · ผลต่าง → กำไร/ขาดทุนอัตราแลกเปลี่ยนที่เกิดขึ้นจริง
- ปรับมูลค่าสิ้นงวด (ยังไม่เกิดขึ้นจริง) + กลับรายการต้นงวดถัดไป — **เปิด/ปิดด้วย config**
- VAT: ฐานและภาษีเป็นบาทเสมอ · ขายส่งออก vat_code `zero` (มีแล้ว) แสดงในรายงานภาษีขายช่อง 0%
- สาขา: เลขที่เอกสารแยกต่อสาขา (config) · รายงานภาษีขาย/ซื้อ + ภ.พ.30 กรองสาขา · ยื่นแยก/รวม = config
- บัญชีโมดูล: 4910100 กำไรจากอัตราแลกเปลี่ยน · 5920100 ขาดทุนจากอัตราแลกเปลี่ยน (ไม่ใช้ 4900100 เดิมเพื่อไม่กระทบ fixtures)

## SWT — สัญญา/รายได้รับล่วงหน้า + ภาษีจ่ายต่างประเทศ
- ตาราง: `contract` (ลูกค้า วันเริ่ม/สิ้นสุด รอบบิล ต่ออายุอัตโนมัติ สถานะ) · `contract_line` (สินค้า/บริการ ประเภท license|subscription|support|implementation|usage · ยอด · วิธีรับรู้ point_in_time|ratably|milestone) · `revenue_schedule` (บรรทัดสัญญา งวด ยอด journal_id) · `usage_record` (รับยอดใช้งานผ่าน API)
- รอบบิล: สร้าง IV **ร่าง** จากสัญญาตามรอบ (ไม่ผ่านรายการเอง — ผู้ใช้อนุมัติ) · usage → บรรทัดตามยอดใช้
- IV ของบรรทัด ratably → Cr รายได้รับล่วงหน้า แทนรายได้ · ตารางรับรู้รายเดือน (pro-rate ตามวัน) · ปิดงวด/ปุ่มรัน → JV Dr รายได้รับล่วงหน้า / Cr รายได้ (เหมือนค่าเสื่อม · รันได้ครั้งเดียวต่องวด)
- ตัวชี้วัด: MRR · ARR · backlog (รายได้ที่ยังไม่รับรู้) · churn รายเดือน
- **ภ.พ.36**: AP/EXP จากผู้ขายต่างประเทศ (contact.entity_type = foreign) บรรทัดบริการ → ตอนจ่าย: Dr ภาษีซื้อรอใช้สิทธิ (ภ.พ.36) / Cr ภาษี ภ.พ.36 ค้างนำส่ง · ยื่นแล้วโอนเป็นภาษีซื้อเดือนถัดไป · รายงาน ภ.พ.36
- **ภ.ง.ด.54**: หัก ณ ที่จ่ายจ่ายต่างประเทศ · อัตราตามประเภทเงินได้ × ประเทศ (ตาราง config อนุสัญญา) · รายงาน ภ.ง.ด.54 · ผู้จ่ายออกภาษีแทน (gross-up) = config
- **สินทรัพย์ไม่มีตัวตน**: fixed_asset ประเภท intangible ใช้ค่าเสื่อมเดิม (ตัดจำหน่าย) · บัญชีแยก
- บัญชีโมดูล: 2170100 รายได้รับล่วงหน้า · 1170200 ภาษีซื้อรอใช้สิทธิ (ภ.พ.36) · 2150500 ภาษี ภ.พ.36 ค้างนำส่ง · 2150600 ภาษีหัก ณ ที่จ่าย ภ.ง.ด.54 ค้างนำส่ง · 1600100 สินทรัพย์ไม่มีตัวตน-ซอฟต์แวร์ · 1600190 ค่าตัดจำหน่ายสะสม · 5150400 ค่าตัดจำหน่าย
